Pares com correlação POSITIVA (confirmação)

e0 - Trend técnico + modelo ML de direção

Trend: EMA cross / breakout.

ML: LightGBM com lags, RSI (7/14/21), ATR, volatilidade realizada (14/30), slopes lineares, mom10/mom20, desvios das EMAs e hora do dia.

Uso: só entra quando ambos concordam; exige menos trades e melhora precision.

e1 - Sinais multiframe

Higher TF (ex.: 1h): filtro de tendência (EMA slow).

Lower TF (ex.: 5m): gatilho (pullback/RSI) + ATR relativo. Incluímos volatilidade do TF superior para medir regime.

Uso: concordância de timeframes costuma aumentar o hit rate.

e2 - Cointegração (VECM) + técnico de spread

VECM: indica desvio do equilíbrio entre dois ativos.

Técnico: Bollinger no spread para gatilho.

Uso: quando ambos sinalizam convergência, reforça o trade de pairs. Agora também acompanhamos correlação rolling (60/120) e z-score do spread sobre janela longa para reforçar confiança.

e3 - forma de candles (corpo/pavio), padrões simples (doji, hammer, engulfing) e contagens rolling

Uso: Esse especialista (“Pattern”) não é um algorítmo isolado, mas um conjunto de features que o MoE usa para detectar padrões de candle. Ele olha para a forma da vela e gera sinalizadores numéricos:
Medidas básicas: corpo, sombras, proporções, tudo normalizado pelo ATR (body_atr, upper_wick_atr, etc.).
Flags clássicas:
doji_flag: corpo muito pequeno (|corpo| / range < 0.1).
hammer_flag: sombra inferior ≥ 2× corpo e sombra superior ≤ 0.5× corpo.
shooting_star_flag: espelho do hammer (sombra superior longa).
bullish_engulf_flag / bearish_engulf_flag: corpo atual engolindo o anterior.
Contagens rolling:
hammer_roll3: média dos hammers nas últimas 3 velas.
shooting_star_roll3: idem para shooting star.
engulf_diff_roll5: diferença entre engolfos altistas e baixistas nos últimos 5 candles.
Novos sinalizadores: gaps (gap_up/gap_down), wick imbalance (diferença entre pavios normalizada), direção do corpo, médias móveis das proporções de corpo.
O “expert Pattern” recebe justamente essas colunas do dataframe (doji_flag, hammer_flag, body_atr, engulf_diff_roll5) e, via MLP, decide se vale apostar em reversão/continuação. Ele não tem lógica if/else própria — aprende a usar essas features com o PPO, como se fosse um operador humano treinando olho para candles.

Validação:
- Walk-forward agora roda Monte Carlo com ruído em preço/feature, stress de custo (±50%), lags 1–5 barras e classifica os resultados por regime de volatilidade (low/mid/high).
- Para auditoria rápida fora do WF, o script `scripts/stress_tests.py` aplica os mesmos cenários sobre o `moe_policy_final.pt` e gera JSON/Markdown em `reports/train/`.
- Logging opcional via Weights & Biases (`logging.wandb` no config) para comparar runs e versionar artefatos; fallback continua sendo CSV/plots locais.
- Testes unitários básicos (`pytest -q`) garantem que o gating normalize pesos/top-k e que o ambiente responda a passos simples sem quebrar.

Curriculum: o treino começa com episódios mais fáceis (sem random_start, janela maior) e rollouts menores; gradualmente libera o regime completo (`train.curriculum`). Isso acelera a estabilização da política antes de expor todo o histórico.

Otimização: existe um fluxo Optuna (`optimize.py`) que varre lr/gamma/top_k/entropia, aproveitando o curriculum curto para avaliar rapidamente qual combinação entrega maior greedy equity. O melhor resultado gera um `best_config.json` para atualizar a configuração principal.
