Distribucional > pontual: prever quantis (p.ex. 0.1/0.5/0.9) ou parâmetros de uma distribuição (média/variância). Isso lida melhor com incerteza e ruído.

Horizonte

“Próximo candle” pode ser 1 bar à frente (1-step) ou multi-horizonte (1, 2, 3… N passos). Multi-horizonte é útil para decidir hold time.

Entrada (features)

OHLCV normalizados (z-score por ativo ou robust scaler), retornos passados, volatilidade (ATR, std. móvel), volume e time-of-day (seno/cosseno).

Evite leakage: nenhuma feature pode usar informação do futuro.

2) Arquiteturas que funcionam

Você tem 3 famílias fortes para séries financeiras (todas melhores que “um GPT puro” na prática):

Transformers para séries

PatchTST, Informer, TimesNet, Temporal Fusion Transformer (TFT).

Vantagem: capturam padrões longos, saídas multi-horizonte, incerteza via quantile loss.

Redes clássicas de forecasting

N-BEATS / N-HiTS (fortes em univariate e multivariada curta).

Modelos probabilísticos

DeepAR/DeepState (autoregressivos probabilísticos), ou cabeça Gaussiana/Student-t em qualquer backbone.

Se quiser “sabor GPT”: use um Transformer decoder-only causal, máscara triangular, onde “tokens” são vetores de features por candle. A cabeça de saída prevê quantis do retorno.

5) Validação correta (evite overfitting)

Walk-forward / expanding window.

Purged & Embargoed CV (López de Prado): remove vazamento entre folds sequenciais.

Métricas: MAE quantílico, CRPS, Hit ratio (direção), Information ratio do PnL com custos.

6) Pipeline mínimo

Baixe e alinhe OHLCV (mesmo timezone, sem bad ticks).

Crie janelas: X = [t-L … t], y = alvo em t+1 (ou t+1..t+H).

Normalize com estatísticas do train (aplique no val/test).

Treine (early stopping por perda em val).

Construa política de trade a partir da previsão.

Backtest walk-forward com custos e slippage.

Analise leverage, drawdown, exposure.

7) Esqueleto PyTorch (Transformer causal + quantis)

Ilustrativo, foca no próximo retorno de fechamento e três quantis.
(Para multi-horizonte, basta a cabeça prever [batch, H, Q]).

import torch, torch.nn as nn, torch.nn.functional as F

class QuantileLoss(nn.Module):
    def __init__(self, quantiles=(0.1, 0.5, 0.9)):
        super().__init__()
        self.q = torch.tensor(quantiles)

    def forward(self, pred, target):
        # pred: [B, Q], target: [B]
        e = target.unsqueeze(-1) - pred
        q = self.q.to(pred.device).unsqueeze(0).expand_as(e)
        return torch.mean(torch.maximum(q*e, (q-1)*e))

class CandleTransformer(nn.Module):
    def __init__(self, d_in, d_model=128, nhead=4, nlayers=4, seq_len=128, quantiles=(0.1,0.5,0.9)):
        super().__init__()
        self.input_proj = nn.Linear(d_in, d_model)
        enc_layer = nn.TransformerEncoderLayer(d_model=d_model, nhead=nhead, batch_first=True)
        self.encoder = nn.TransformerEncoder(enc_layer, num_layers=nlayers)
        self.pos = nn.Parameter(torch.randn(1, seq_len, d_model) * 0.01)
        self.head = nn.Linear(d_model, len(quantiles))

    def forward(self, x):
        # x: [B, L, d_in]  (janelas de candles passados)
        h = self.input_proj(x) + self.pos[:, :x.size(1)]
        # máscara causal: cada passo só vê o passado
        L = x.size(1)
        mask = torch.triu(torch.ones(L, L, device=x.device)*float('-inf'), diagonal=1)
        h = self.encoder(h, mask)
        h_last = h[:, -1]                # usar o último passo
        qhat = self.head(h_last)         # [B, Q] -> quantis do retorno próximo
        return qhat

# uso:
# X: [B, L, d_in], y: [B] (retorno futuro)
model = CandleTransformer(d_in=8, seq_len=128)  # por ex., 8 features (retornos O/H/L/C, volume, ATR, etc.)
crit = QuantileLoss()
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=1e-4)

for X_batch, y_batch in loader_train:
    qhat = model(X_batch)
    loss = crit(qhat, y_batch)
    opt.zero_grad(); loss.backward(); opt.step()


Notas práticas

Na entrada, coloque retornos de O/H/L/C, log-volume, ATR/Close, time-of-day (seno/cosseno).

Para multi-ativo, some um embedding por ativo.

Para multi-horizonte, troque head para produzir [B, H, Q] e some uma temporal query de horizonte.

9) Armadilhas comuns

Leakage (normalizar com info do futuro, usar indicadores que “espiam”).

Overfitting por look-ahead bias e hyperparameter fishing.

Ignorar custos e slippage. Em intraday, podem engolir todo o edge.

Usar PnL do train como métrica principal (prefira val/test walk-forward).

10) Extensões úteis

Ensembles (PatchTST + N-BEATS + regressão linear de baseline).

Regime switching: classificar regime (alta vol, baixa vol) e usar cabeça específica.

Exógenas: calendário, macro (quando for swing/diário), news sentiment (alinhado temporalmente).

RL na camada de decisão: mantenha o modelo de previsão e treine a política por cima (ex.: PPO) usando as previsões como estado — separa forecasting de execution.

Checklist executável

 Defina alvo (retorno 1-bar) e horizontes (1, 3, 5 barras).

 Crie dataset com janelas L=128, features padronizadas.

 Treine Transformer causal com quantile loss (0.1/0.5/0.9).

 Valide com walk-forward + embargo.

 Construa regra de trade com custos e position sizing.

 Reporte: hit ratio, PnL com custos, IR, MDD, turnover.

Aviso rápido: isso é material educacional, não é aconselhamento financeiro. Sempre teste exaustivamente e inclua custos reais.
